architecture

Visitors reach the portfolio through Cloudflare DNS. Traffic is served by CloudFront over HTTPS. CloudFront accesses a private S3 origin through Origin Access Control. Infrastructure is provisioned with Terraform.

Public entry point

CloudFront is the only public entry point and handles TLS, caching, and security headers.

Private origin

The S3 bucket remains private and is reachable only through CloudFront using OAC.

Infrastructure ownership

Terraform provisions the infrastructure and GitHub Actions handles automated delivery.

terraform_design

Terraform keeps the portfolio infrastructure reproducible and low-maintenance by composing focused modules around a single environment root. The design separates backend bootstrap, runtime resources, and CI/CD identities while keeping the deployment workflow straightforward.

Remote state

Encrypted S3 backend with native .tflock locking.

Focused modules

Small modules with explicit responsibilities and clear contracts.

Explicit dependencies

Outputs connect modules and make resource relationships visible.

cicd

Automated delivery and explicit trust boundaries keep AWS credentials temporary, permissions scoped, and infrastructure and content delivery responsibilities separate.

No long-lived AWS credentials in GitHub.AWS access is granted just-in-time through GitHub OIDC.

Delivery pipelines

01

Infrastructure pipeline

PRs run static validation only. Push and manual runs revalidate, pass through the dev environment, assume the Terraform role, then run init, plan and apply.

02

Website delivery pipeline

PRs validate the build without deploying. Main and manual runs build a fresh artifact, then a restricted publishing role synchronizes S3 metadata and invalidates CloudFront.

engineering_decisions

The project stays intentionally small, but the delivery model is opinionated. Each decision favors private-by-default delivery, reproducible infrastructure, and low operational overhead for a personal portfolio.

ⓘ

These choices trade a small amount of setup complexity for clearer boundaries and safer automation.

1

Private S3 origin

Choice
CloudFront with OAC instead of public S3 website hosting
Why
Keeps the bucket private and makes CloudFront the only public content entry point
Trade-off
Requires additional origin access configuration and bucket policies
2

Cloudflare + ACM

Choice
Keep authoritative DNS in Cloudflare while using ACM and CloudFront for HTTPS
Why
Preserves existing DNS management while keeping content delivery on AWS
Trade-off
Cross-provider Terraform and automated DNS validation add coordination
3

Separate delivery paths

Choice
Split infrastructure changes from website content deployments
Why
HTML, CSS and JavaScript updates do not require a Terraform apply
Trade-off
Requires separate workflows, roles and deployment logic
4

Bootstrap outside CI/CD

Choice
Handle backend and IAM bootstrap outside routine automation
Why
Prevents normal delivery pipelines from controlling their own trust boundary
Trade-off
Sensitive IAM and bootstrap changes remain privileged operator tasks
  • Private by default
  • Least privilege
  • Low operational complexity

trade_offs

The project is intentionally scoped for a personal portfolio. It prioritizes reproducibility, security, and low operational overhead over production-grade resilience features that would add complexity and cost.

ⓘ

These constraints are deliberate design choices, not missing fundamentals.

1

Single dev environment

Choice
One dev environment keeps the project simple and reproducible.
Trade-off
No staging/production split or artifact promotion workflow.
2

PriceClass_100

Choice
CloudFront edge coverage is intentionally limited to control CDN cost.
Trade-off
Less geographic coverage than broader CloudFront price classes.
3

Full invalidation

Choice
Invalidate the full CloudFront distribution with /* after deployment.
Trade-off
Less efficient than targeted invalidation, but simpler at this scale.
4

Explicit cache strategy

Choice
HTML is no-cache, hashed CSS/JS is immutable, and other assets cache for one hour.
Trade-off
The deployment must apply object metadata in multiple passes.
5

No advanced resilience layer

Choice
No WAF, origin failover, or cross-region replication is provisioned.
Trade-off
Lower complexity and cost, but fewer resilience and edge-security capabilities.
6

Redeploy-based recovery

Choice
Recover a partial or failed publish by redeploying a complete known-good build.
Trade-off
Recovery requires a clean workflow rerun instead of an automatic atomic rollback.
  • Low cost
  • Low maintenance
  • Deliberate scope
